## 1. Executive Summary

바쁜 직장인이 매일 30초로 습관을 체크하면, AI가 주간 요약을 만들고 사람 코치가 그 요약을 보고 5분 안에 피드백을 남기는 구독형 코칭 서비스다. 코치는 "지난주 어땠나요?"를 묻는 데 시간을 쓰지 않으므로 한 명이 많은 사용자를 맡을 수 있고, 사용자는 1:1 코칭보다 낮은 비용으로 사람의 피드백을 받는다. 지금 습관 추적 앱은 코치가 볼 데이터를 쌓는 입력 도구가 된다.

**Phase 1은 코치 1~2명, 사용자 20~30명 규모의 콘시어지 파일럿이다.** 결제, 마켓플레이스, 화상 예약 자동화는 파일럿 결과를 본 뒤 결정한다.

## 2. Background & Context

### 문제
- 개인 코칭은 효과가 있다고 알려져 있지만 비싸고 일정 잡기가 어렵다.
- 코치의 세션 시간 상당 부분이 지난 기간을 확인하는 데 쓰인다.
- 기존 습관 앱은 기록은 남기지만 그 기록을 해석해 주는 사람이 없다. 연속 기록이 끊기면 벌처럼 느껴져 이탈한다.

### 타깃 가설
바쁜 직장인은 (1) 시간이 부족하고, (2) 자신이 한 약속을 꾸준히 지키는 것을 중요하게 여기며, (3) 개인 코칭에 비용을 지불할 의향이 있을 수 있다. 세 번째는 아직 검증되지 않았다.

### 현재 제품 자산과 격차
| 항목 | 현재 | 코칭에 필요한 것 |
|---|---|---|
| 습관 체크, 캘린더, 통계 | 있음 (React, 로컬 저장) | 유지. 미완료 사유 입력 추가 |
| 계정 | 이 기기 브라우저 안의 로컬 프로필 (서버·비밀번호 없음) | **서버 계정과 실제 인증** |
| 데이터 저장 | `localStorage` | **서버 DB.** 코치가 사용자 데이터를 볼 수 있어야 함 |
| 요약 | 통계 화면(수치) | 주간 요약 리포트(수치 + 해석 문장) |
| 코치 화면 | 없음 | 코치 콘솔 |
| 결제 | 없음 | Phase 2 |

### 왜 지금
파일럿 비용이 낮다. 코치 1~2명과 스프레드시트만으로도 "요약 → 피드백 → 목표 조정" 루프를 먼저 검증할 수 있다. 다만 이 방향의 성패는 코치 원가와 구독료의 관계(단위경제)에 달려 있어서, 코치가 사용자당 실제로 쓰는 시간을 가장 먼저 측정해야 한다.

## 3. Objectives & Success Metrics

### Goals
1. 사용자가 일일 체크를 습관으로 유지하게 한다(30초 이내).
2. 코치가 사용자당 **주 5분 이내**로 유용한 피드백을 남길 수 있음을 증명한다.
3. 피드백이 다음 주 목표 조정으로 이어지는 루프가 실제로 돌아가는지 확인한다.
4. 사용자가 이 서비스에 돈을 낼지, 얼마까지 낼지 데이터로 답한다.

### Non-Goals
1. **코치 마켓플레이스와 코치 온보딩** — 공급 모델은 파일럿 뒤에 결정한다.
2. **의료·심리 상담** — 스트레스, 번아웃, 정신건강 상담은 범위 밖이다. 그런 신호는 전문기관 안내로 연결한다.
3. **코치를 AI로 대체** — AI는 요약과 초안 작성만 맡고, 피드백의 최종 책임은 코치에게 있다.
4. **실시간 채팅** — 코치 응답 시간 보장이 어렵고 코치 원가를 키운다.
5. **네이티브 모바일 앱, 기업(B2B) 플랜, 캘린더 연동** — 이후 단계.
6. **자동 결제와 코치 정산** — Phase 1은 무료 파일럿이거나 수동 청구다.

### Success Metrics
현재 값은 모두 미측정이다(제품에 사용자 없음). 목표는 파일럿 종료 시점(6주) 기준의 **초기 가설**이며, 첫 2주 데이터로 재조정한다.

| 지표 | 현재 | 목표(가설) | 측정 방법 |
|---|---|---|---|
| 활성화: 가입 후 7일 안에 3일 이상 체크한 사용자 비율 | 미측정 | 60% 이상 | 서버 체크 로그 |
| 4주차 유지율(4주차에도 주 3일 이상 체크) | 미측정 | 40% 이상 | 서버 체크 로그 |
| 코치 처리 시간 중앙값(사용자당 주간 피드백) | 미측정 | 5분 이하 | 코치 콘솔이 피드백 열기~전송 시간 기록 |
| 피드백 SLA: 요약 생성 후 48시간 안에 피드백이 전달된 비율 | 미측정 | 90% 이상 | 요약·피드백 타임스탬프 |
| 피드백 유용성("다음 주 계획에 도움이 됐다") 평균 | 미측정 | 5점 만점에 4점 이상 | 피드백 카드의 1탭 평가 |
| 주간 이행률 변화(1~2주차 대비 5~6주차) | 미측정 | +10%p 이상 | 서버 체크 로그 |
| 유료 의향: 파일럿 종료 시 "이 가격이면 계속 쓰겠다" 응답 비율 | 미측정 | 20% 이상 | 종료 설문 + 가격 제시 인터뷰 |

**가드레일 지표:** 피드백 전달 실패율, 사용자 삭제·동의 철회 요청 수, 위기 신호 안내가 표시된 횟수와 코치 확인율.

## 4. Target Users & Segments

### 주 사용자: 바쁜 직장인 (가설)
- 근무 시간이 길고 일정이 자주 바뀌어 습관을 놓친다.
- 약속(운동, 독서, 학습, 수면 등)을 지키지 못했을 때 자기 신뢰가 떨어진다고 느낀다.
- 혼자 하는 기록 앱에는 지쳤고, 사람의 피드백에는 관심이 있다.
- **아직 모르는 것:** 실제 규모, 지불 가능 금액, 코칭에서 기대하는 것(동기부여 / 계획 조정 / 책임감).

### 코치 (공급 측)
- Phase 1은 운영팀이 직접 섭외한 1~2명.
- 필요한 것: 사용자 데이터를 한 화면에서 빠르게 훑고, 초안을 고쳐서 보내는 도구.

### 세분화 가설 (파일럿에서 검증)
| 세그먼트 | 특징 | 검증 질문 |
|---|---|---|
| 계획 조정형 | 목표는 있는데 현실적인 계획이 안 됨 | 주간 목표 조정 피드백이 가장 큰 가치인가 |
| 책임감형 | 누가 봐준다는 것이 동기 | 피드백 여부가 유지율에 영향을 주는가 |
| 자기 이해형 | 왜 못 지켰는지 알고 싶음 | 미완료 사유 분석을 유용하다고 보는가 |

## 5. User Stories & Requirements

### P0 — Must Have (Phase 1)

| # | User Story | Acceptance Criteria |
|---|---|---|
| P0-1 | 사용자로서, 이메일로 가입하고 로그인해서 어느 기기에서든 내 습관을 보고 싶다. | 서버에 계정이 생성된다. 로그인 후 어느 브라우저에서든 같은 데이터가 보인다. 기존 로컬 계정의 습관·기록을 가입 시 서버로 옮길 수 있다(선택). |
| P0-2 | 사용자로서, 매일 30초 안에 오늘 습관을 체크하고 싶다. | 기존 Today 화면의 체크 흐름이 유지된다. 습관 3개 기준 체크 완료까지 클릭 3회 이하. |
| P0-3 | 사용자로서, 못 지킨 날 이유를 한 번 탭으로 남기고 싶다(선택). | 하루가 지난 미완료 항목에 사유 5~6개(시간 부족, 우선순위 변경, 잊음, 컨디션, 기타 등)가 표시된다. 선택하지 않아도 넘어갈 수 있다. |
| P0-4 | 사용자로서, 코치와 내 데이터를 공유하는 것에 명시적으로 동의하고 싶고, 언제든 철회하고 싶다. | 가입 직후 공유 범위(습관명, 체크 기록, 사유)와 목적을 설명하는 동의 화면이 나온다. 동의 전에는 코치에게 데이터가 보이지 않는다. 설정에서 철회하면 코치 화면에서 즉시 사라진다. |
| P0-5 | 사용자로서, 지난 한 주의 요약을 받고 싶다. | 매주 정해진 시각에 요약이 생성된다. 요약에는 이행률, 전주 대비 변화, 요일별 패턴, 미완료 사유 분포, 가장 잘 지킨 습관과 가장 자주 놓친 습관이 들어간다. **수치는 코드로 계산하고 AI는 문장 생성만 맡는다**(수치가 생성 과정에서 바뀌지 않도록). |
| P0-6 | 코치로서, 담당 사용자의 주간 요약을 한 화면에서 보고 피드백을 쓰고 싶다. | 코치 콘솔에 담당 사용자 목록(피드백 대기 / 완료)이 보인다. 사용자 선택 시 요약과 최근 4주 추세가 보인다. AI가 피드백 초안을 제안하고 코치가 수정해서 전송한다. |
| P0-7 | 사용자로서, 코치의 피드백을 앱 안에서 받고 알림을 받고 싶다. | 피드백 전송 시 이메일 알림이 간다. 앱에서 요약과 피드백이 함께 보인다. 읽음 상태와 1탭 유용성 평가가 저장된다. |
| P0-8 | 사용자로서, 피드백을 보고 다음 주 목표를 조정하고 싶다. | 피드백 화면에서 습관 추가·수정·삭제로 바로 이동할 수 있다. 조정 후 "다음 주 계획 확정"을 누르면 기록된다. |
| P0-9 | 서비스 운영자로서, 코칭 범위를 벗어난 위기 신호를 안전하게 다루고 싶다. | 사용자 입력(사유 기타, 메모)에서 위기 관련 표현이 감지되면 코치에게 표시되고, 사용자에게는 전문기관 안내가 나온다. 코치 피드백 화면에 "이 서비스는 의료·심리 상담이 아닙니다" 안내가 상시 표시된다. 감지 기준은 코치·법무와 확정한다. |
| P0-10 | 서비스 운영자로서, 코치별 처리 시간을 측정하고 싶다. | 코치 콘솔이 피드백 열기, 전송 시각과 소요 시간을 기록한다. 지표 3장의 코치 처리 시간을 대시보드나 내보내기로 확인할 수 있다. |

## 6. Solution Overview

### 6.1 핵심 루프

```
[일일] 체크(30초) → 미완료 사유(선택)
   ↓ 매주 정해진 시각
[주간] 요약 자동 생성 (수치 계산 + AI 문장)
   ↓
[코치] 요약 열람 → AI 초안 수정 → 전송 (목표 5분)
   ↓
[사용자] 피드백 확인 → 다음 주 목표 조정 → 확정
   ↓ 월 1회 (상위 티어)
[월간] 15분 화상 체크인
```

### 6.2 주요 화면
- **사용자 앱(기존 확장):** Today, Calendar, Statistics, Data에 더해 `Weekly`(주간 요약과 코치 피드백, 목표 조정) 화면을 추가한다. 사이드바와 하단 탭 구조는 그대로 쓴다.
- **코치 콘솔(신규):** 담당 사용자 목록(대기/완료), 사용자 상세(요약, 4주 추세, 사유 분포), 피드백 작성기(AI 초안 + 편집), 비공개 메모(P1).
- **운영 화면(최소):** 배정, 코치별 처리 시간, 피드백 SLA. Phase 1에서는 스프레드시트나 SQL 쿼리로 대체할 수 있다.
- 디자인은 `design.md`를 따른다. 코치 콘솔에도 형광 노랑은 "다음 행동"에만 쓴다.

### 6.3 주간 요약 파이프라인 (핵심 설계 결정)
1. **계산 단계(결정적):** 이행률, 전주 대비, 요일별 패턴, 사유 분포, 최고·최저 습관을 코드로 계산한다.
2. **문장화 단계(AI):** 계산 결과를 입력으로 받아 요약 문장과 코치용 피드백 초안을 만든다. AI 출력에 계산 결과에 없는 수치가 나오면 검증에서 걸러낸다.
3. **검수 단계(사람):** 코치가 초안을 수정해서 전송한다. 사용자에게 가는 피드백은 항상 코치가 승인한 것이다.
- 이유: 코칭 신뢰는 "수치가 맞다"에 달려 있다. 수치 생성을 AI에 맡기면 잘못된 피드백이 한 번만 나가도 신뢰를 잃는다.

### 6.4 데이터 모델 (초안)
`users`, `habits`, `completions`(+ `miss_reason`), `weekly_summaries`, `coach_assignments`, `feedback`(+ `rating`, `read_at`, `sent_at`, `opened_at`), `consents`(범위, 동의·철회 시각), `coach_notes`. 날짜는 사용자 로컬 날짜 키(`YYYY-MM-DD`)를 유지한다.

### 6.5 구독 티어 (가설, 가격은 파일럿 후 확정)
| 티어 | 포함 | 코치 시간 |
|---|---|---|
| Basic | 일일 체크, AI 주간 요약 | 없음 |
| Coach | + 주간 서면 피드백, 목표 조정 | 주 5분 이하 |
| Coach+ | + 월 1회 15분 화상 체크인 | 주 5분 + 월 15분 |

### 6.6 주요 위험과 완화

| 위험 | 완화 |
|---|---|
| 코치 인건비가 구독료를 넘어 성장할수록 적자 | 코치 처리 시간을 첫 주부터 측정(P0-10). 5분 목표를 못 맞추면 티어·가격·도구를 조정한 뒤 확장한다 |
| 코치 품질 편차 | 파일럿은 2명 이하 직접 섭외. 유용성 평가(P0-7)로 코치별 비교 |
| 의료·심리 상담과의 경계 | 범위 밖 선언(비목표 2), 위기 신호 처리(P0-9), 코치 가이드라인 |
| 개인정보(습관 기록이 민감할 수 있음) | 명시적 동의와 철회(P0-4), 삭제(P1-6), 최소 수집. 법무 검토를 파일럿 시작 전에 완료 |

| 사용자가 코칭 가치를 못 느끼고 이탈 | 2주 차에 피드백 유용성 지표 점검, 피드백 형식 실험 |

## 8. Timeline & Phasing

일정은 엔지니어링 투입 인원이 정해지지 않은 상태의 **추정**이다. 인원 확정 후 조정한다.

### Phase 0 — 검증 (2주, ~2026-10-12)
- 바쁜 직장인 인터뷰 8~10명: 습관 앱 이탈 이유, 코칭 지불 의향, 원하는 피드백 형태.
- 코치 후보 인터뷰, 개인정보·법무 확인 착수.
- **진행 조건:** 인터뷰에서 절반 이상이 "사람의 피드백에 돈을 낼 수 있다"고 답하지 않으면 방향 A 또는 B로 되돌아가는 것을 검토한다.

### Phase 1 — 콘시어지 파일럿 (6주, 2026-10-13 ~ 2026-11-23)
- 범위: P0 전체. 운영 화면은 스프레드시트·SQL로 대체 가능.
- 규모: 코치 1~2명, 사용자 20~30명, 무료 또는 수동 청구.
- 주차별 점검: 2주차에 코치 처리 시간·유용성 1차 점검, 4주차에 유지율, 6주차에 유료 의향 인터뷰.
- **종료 판정:** 코치 처리 시간, 유지율, 유료 의향 세 지표를 3장 목표와 비교해 Phase 2 진행 여부를 결정한다.

### Phase 2 — 제품화 (약 8주, 판정 후)
- P1: 결제와 티어, 화상 체크인 예약 연결, 배정 관리, 알림 설정, 데이터 내보내기·삭제.
- 코치 수를 늘리고 코치별 단위경제를 측정한다.

### Phase 3 — 확장 (별도 PRD)
- 마켓플레이스, 팀 플랜, 캘린더 연동(P2 항목).

### 의존성
- 개인정보·법무 확인(Open Questions 5, 6, 9)은 **Phase 1 시작 전** 완료해야 한다.
- 백엔드 선택(Open Question 7)이 P0-1, P0-5의 개발 착수 조건이다.
- 코치 섭외(Open Question 4)가 Phase 1 시작 조건이다.
